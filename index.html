第一部分 · API · 是什么

API 就像餐厅的点单方式

API（Application Programming Interface，应用程序编程接口）是程序之间事先约定好的沟通格式。你的工具按格式“点单”，模型在后厨做好再“上菜”。你不用进后厨，也不用会做菜。

在餐厅里换成 AI
顾客你的工具：表格、问卷、批改系统
菜单API 文档：能点什么、该怎么点
服务员API：把订单送进后厨，再把菜端回来
后厨大模型所在的服务器
会员卡API Key：证明你是谁，从谁的账上扣钱

网页聊天 = 堂食

  • 你打一句，它回一句
  • 一次处理一件事
  • 结果靠手动复制粘贴

API = 团餐接口

  • 程序替你发请求
  • 一次处理 50 篇、500 条
  • 结果自动回到表格或系统里

背后是同一个模型：网页给人用，API 给程序用。

你其实天天在用 API： 外卖 App 里的地图 “用微信登录” 天气 App 的数据 多维表格里的 AI 列

    API · 两个常见词
    
        
    Token 和 API Key
    
      
    
      
    
        
    
          
    Token
    
          
    AI 读写和计费的单位
    
          
      
            
    • 像按字数付稿费：读进去的、写出来的都算
      • 
            
    • 文字被切成小块：英文常是一个词或半个词，中文一般一两个字一块
      • 
            
    • 不同模型切法不同，可以在网上找个 tokenizer 工具，看看自己的句子被切成几块
      • 
          
    
        
    
        
    
          
    API Key
    
          
    一张能扣钱的门禁卡
    
          
      
            
    • 谁拿到它，谁就能用你的账户调用、扣你的余额
      • 
            
    • 不发群、不截图、不写进公开文档
      • 
            
    • 万一泄露：去平台上删掉，重新生成一把
      • 
          
    
        
    
      
    
    
    
  
    

  
  
    
    
    
      
    
        
    第二部分 · RAG · 是什么
    
        
    RAG：让 AI 开卷考试
    
        
    大模型像一个在考闭卷的学霸，有三个短板。RAG（Retrieval-Augmented Generation，检索增强生成）的办法是让它开卷：先翻书，再作答。
    
      
    
      
    
        
    记不准细节会记混，不会也能写得头头是道，这就是“幻觉”
    
        
    不够新知识停在训练结束的那一天，之后的新政策、新教材都不知道
    
        
    没读过校本教材、教研组规定、你的课程大纲，它从来没见过
    
      
    
      
    
        
    RRetrieval检索先翻书：从资料库里找出和问题最相关的几段
    
        →
        
    AAugmented增强夹进题目：把这几段资料和问题拼在一起，交给模型
    
        →
        
    GGeneration生成照着作答：模型根据这几段回答，并注明出处
    
      
    
      
    
        
    准备阶段（只做一次）
    资料 → 切成一段一段 → 给每段算出“意义坐标” → 存进资料库
    
        
    提问阶段（每次都走一遍）
    问题 → 去资料库找意思最近的 3–5 段 → 和问题拼成提示词 → 模型作答并注明出处

      语言学在这里
      
        
      
          
      “You shall know a word by the company it keeps.”
      
          
      J. R. Firth，1957
      
        
      
        
      一个词的意思，要看它常和哪些词一起出现，这是分布语义学的基本想法。AI 给文字算“意义坐标”，靠的正是这个思路：你们学过的语言学，就是 AI 检索的地基。
      
      
      
    
      
  
      

  
  
      
    
      
      
      
        
      怎么用
      
        
      回到自己的课堂：怎么用起来
      
      
      
      
      
        
      
          
      API
      
          
      三种不写代码的方式
      
          
      
            
      表格里的 AI 列飞书多维表格等：加一列 AI，写好提示词，整列自动生成。适合一批数据逐条处理，比如 50 篇作文的评语。
      
            
      智能体平台扣子（Coze）、Dify：拖拽搭建一个小助手，背后调用模型 API。适合做能反复用的工具。
      
            
      几行 Python让 AI 帮你写脚本，你只改提示词和文件名。适合想完全按自己的方式来。
      
          
      
          
      通用步骤

      用 RAG 之前，记住这四个坑
      
      
      
        
      资料里没有它仍可能“补”出一个答案。对策：写明“找不到就说找不到”
      
        
      翻错了页检索到的段落不对，答案就跟着错。对策：换个问法，问得更具体
      
        
      上下文被切断一段话被切成两半，意思就不完整了。对策：资料结构清楚、有小标题
      
        
      隐私与版权学生作文、个人信息，不要随手上传。对策：先匿名化，用学校认可的平台
